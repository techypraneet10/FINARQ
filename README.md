## Overview

Most "chat with your PDF" tools treat the LLM as the source of truth. FINARQ doesn't. It's built around one rule: **the LLM never gets to be the source of truth — the source documents are.**

Every number FINARQ reports is computed deterministically (not generated by a language model), every factual claim is traced back to a specific page and chunk of the original document, and every response comes with a confidence/status label rather than a confident-sounding guess.

**Who it's for:** analysts and engineers who need to query dense financial documents (10-K/10-Q filings, earnings reports, bank statements, loan agreements) and can't afford a hallucinated number.

**What problem it solves:** general-purpose RAG chatbots are good at fluent answers and bad at correctness. Financial documents punish that trade-off — a wrong number in an earnings summary is worse than no answer at all. FINARQ separates *retrieval* (finding the right evidence), *reasoning* (deterministic calculation over that evidence), and *generation* (explaining it in plain language) into distinct, auditable stages instead of asking one model to do all three at once.

## Key Features

- **Hybrid retrieval** — BM25 sparse search + Qdrant dense vector search, combined with Reciprocal Rank Fusion and reranked with a cross-encoder
- **Deterministic financial reasoning** — a decimal-precision calculator (zero-division-safe, 11 operations) does the actual math; the LLM explains results, it doesn't compute them
- **8-stage answer validation** — every generated answer passes through post-generation grounding, citation, and consistency checks before it reaches the user, with a safe deterministic fallback if it fails
- **Page-level citation & provenance** — every factual claim links back to the exact source chunk it came from
- **Layout-aware document processing** — PDF parsing, OCR, and financial table extraction, not just plain-text chunking
- **Multi-tenant by design** — tenant isolation enforced at the row and payload level, not just at the API layer
- **Production security** — JWT auth, 4-tier RBAC, Scrypt password hashing, rate limiting, audit logging
- **Resilience patterns** — circuit breaker, exponential backoff with jitter, semantic error classification
- **Full observability** — distributed tracing, cost tracking, Prometheus metrics
- **Infrastructure as Code** — Terraform-managed AWS deployment (VPC, RDS, S3, ECS Fargate, ElastiCache, ALB) across dev/staging/production

## Architecture

FINARQ follows a layered, hexagonal-style architecture: business logic in `domain/`, use cases in `application/`, and swappable concrete implementations in `infrastructure/`, so the retrieval backend, LLM provider, or storage layer can be replaced without touching business logic.

```
financial-rag-platform/
├── frontend/                    # React 18 + TypeScript intelligence workspace
│   ├── src/api/                 # Typed API client, token rotation, RFC 7807 error parsing
│   ├── src/components/          # Dashboard, Documents, Search, Ask, Evidence, Admin, Jobs
│   ├── src/context/             # Auth (RBAC), Workspace (citations), Theme
│   └── src/design-system/       # Shared UI primitives
├── src/financial_rag/
│   ├── domain/                  # Core models, entities, exceptions, protocols
│   ├── application/             # Use cases: ingestion, retrieval, reasoning, answer orchestration
│   ├── infrastructure/          # Adapters: PDF/OCR, BM25, Qdrant, cross-encoder, JWT, Postgres, S3
│   ├── api/                     # FastAPI routers, auth & RBAC middleware, schemas
│   ├── config/                  # Pydantic Settings — env parsing, secret masking
│   └── worker.py                # Background ingestion worker daemon
├── infra/                       # Terraform modules (VPC, RDS, S3, Qdrant, Redis, ECS, ALB)
├── tests/                       # Unit, integration, load, and deployment test suites
└── docs/decisions/              # 48 Architecture Decision Records
```

**Answer flow:** a query enters the API → hybrid retrieval pulls candidate chunks (BM25 + dense vector) → fusion + reranking narrows to the best evidence → the reasoning layer performs any deterministic calculation → the LLM synthesizes a natural-language answer grounded in that evidence → the answer passes 8 validation stages before being returned with citations and a confidence status.

## Tech Stack

**Frontend**
React 18, TypeScript, Vite, Tailwind design tokens, Vitest

**Backend**
FastAPI + Uvicorn (ASGI), Python 3.11+, Pydantic v2, asyncio ingestion worker

**AI / Retrieval**
BM25 (sparse), Qdrant (dense vector), Reciprocal Rank Fusion, cross-encoder reranking, provider-agnostic LLM layer (OpenAI-compatible)

**Database & Storage**
PostgreSQL 16 (SQLAlchemy 2.0 + Alembic migrations), AWS S3 / MinIO, Redis

**Security**
JWT auth, 4-tier RBAC, Scrypt hashing, rate limiting, audit logging

**Infrastructure**
Terraform (VPC, RDS, S3, Qdrant, ElastiCache, ECS Fargate, ALB), Docker Compose, hardened multi-stage Docker images (non-root user)

**Testing**
Pytest (unit, integration, load, deployment suites) + Vitest

## Installation

**Prerequisites:** Docker & Docker Compose, Node.js 18+ (for local frontend dev), Python 3.11+ (for local backend dev)

```bash
# Clone the repo
git clone https://github.com/techypraneet10/financial-rag-platform.git
cd financial-rag-platform

# Configure environment
cp .env.example .env

# Start the full stack — API, worker, frontend, Postgres, Qdrant, MinIO, Redis
docker compose up --build
```

Once it's running:

| Service | URL |
|---|---|
| Frontend workspace | http://localhost:5173 |
| API | http://localhost:8000 |
| API docs (Swagger) | http://localhost:8000/docs |
| Health check | http://localhost:8000/health |
| Prometheus metrics | http://localhost:8000/metrics |
| Qdrant dashboard | http://localhost:6333/dashboard |
| MinIO console | http://localhost:9001 |

### Running the frontend in dev mode

```bash
cd frontend
npm install
npm run dev
# http://localhost:5173, proxies API calls to http://127.0.0.1:8000
```

## Configuration

Copy `.env.example` to `.env` and set values as needed. Never commit real credentials — `.env` is already git-ignored.

```env
LLM_PROVIDER=mock            # or "openai" for real synthesis
OPENAI_API_KEY=your_key_here
DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/financial_rag
QDRANT_URL=http://localhost:6333
SECURITY_JWT_SECRET_KEY=your_secret_here
```

## Usage

```bash
# Run the API server locally
uvicorn financial_rag.main:app --reload --port 8000

# Run the ingestion worker
python -m financial_rag.worker

# Run database migrations
alembic upgrade head

# Rebuild the vector store
python scripts/rebuild_vectors.py --batch-size 50

# Run a load benchmark
python scripts/load_test.py --concurrency 10 --requests 20
```

## Deployment

Terraform-managed AWS deployment across three environments:

```bash
cd infra/environments/dev        # or staging / production
terraform init && terraform apply
```

Provisions: VPC, RDS PostgreSQL, S3, Qdrant, ElastiCache Redis, ECS Fargate compute, and an Application Load Balancer.
